## 1. 앱 개요와 기술 구조

### 앱 소개
- **이름**: 목양교회 기도
- **용도**: 교회 성도를 위한 기도 앱 (기도 타이머·기록·기도제목·알림)
- **주요 기능**
  - 기도 타이머 — 기도 시간 측정 및 날짜별 기록
  - 기도 기록 — 나의 기도 시간을 한눈에
  - 공동 기도제목 — 교회가 함께 품는 기도제목 열람/작성
  - 기도 알림 — 정한 시간에 알림
  - 대시보드 — "기도 시간 TOP 5" 등

### 핵심 아이디어: "한 번 만들어 세 곳에 배포"
실제 앱 코드는 **하나**(웹앱)이고, 안드로이드·iOS는 그 웹앱을 **감싸는 껍데기**입니다.

```
  [웹앱(PWA)]  ← 실제 코드 (여기만 고치면 전부 반영)
      │
      │  (같은 웹 주소를 불러옴)
      ├──────────────┬──────────────┐
      ▼              ▼              ▼
  브라우저        안드로이드앱       iOS앱
 (주소로 접속)   (TWA 껍데기)    (WebView 껍데기)
```

- **웹앱을 수정 → 자동 배포 → 안드로이드·iOS 앱도 자동으로 최신 내용** (앱 자체를 다시 안 올려도 됨)
- 단, **앱 스토어에 표시되는 정보**(스크린샷·설명 등)나 **껍데기 자체의 버전**을 바꿀 때만 스토어에 재제출

## 파트 A — 웹앱(PWA) 배포 (GitHub Pages)

### A-1. 빌드 명령 구분
| 명령 | 용도 |
|---|---|
| `npm run build:web` | 루트 경로 빌드 (로컬 테스트용) |
| `npm run build:pages` | `/mkchurch-prayer` 경로 빌드 (GitHub Pages 배포용, CI가 사용) |

### A-2. 자동 배포 흐름
1. `mkchurch-prayer` 저장소 **main 브랜치에 push**
2. GitHub Actions(`deploy.yml`)가 자동 실행
3. Supabase 시크릿(`EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`)을 넣어 빌드
4. GitHub Pages에 배포
5. **배포 주소**: `https://byunghoonchoi76.github.io/mkchurch-prayer/`

> Supabase 시크릿은 저장소 **Settings → Secrets and variables → Actions** 에 등록되어 있어야 합니다. 없으면 샘플(이름만) 모드로 배포됩니다.

### A-3. 딥링크 200 응답 처리 (중요)
- GitHub Pages는 하위 경로(`/privacy` 등)에 직접 접속 시 기본적으로 404를 반환
- Google Play·App Store가 "계정 삭제 URL" 등을 **HTTP 200**으로 확인하므로, 이게 404면 거부됨
- 해결: `scripts/finish-web-build.js`가 공개 경로마다 `<경로>.html` 파일을 생성
  - 대상 경로: `privacy`, `terms`, `email-refusal`, `account-deletion`, `display`

### A-4. 주요 공개 페이지 (스토어 등록에 사용)
| 페이지 | 주소 |
|---|---|
| 앱 홈/지원 URL | `https://byunghoonchoi76.github.io/mkchurch-prayer/` |
| 개인정보처리방침 | `.../mkchurch-prayer/privacy` |
| 이용약관 | `.../mkchurch-prayer/terms` |
| 계정 삭제 요청 | `.../mkchurch-prayer/account-deletion` |
| 기도시간 디스플레이 | `.../mkchurch-prayer/display` |

## 파트 B — 안드로이드 (Google Play)

### B-1. AAB 만들기 (PWABuilder)
1. [PWABuilder.com](https://www.pwabuilder.com) 접속
2. 웹앱 주소 입력: `https://byunghoonchoi76.github.io/mkchurch-prayer/`
3. 분석 후 **Android → Google Play** 패키지 생성
4. 패키지 이름(Package ID): **`church.mokyang.guri`**
5. 생성된 zip 안에:
   - `*.aab` (Google Play 업로드 파일)
   - `signing.keystore` + `signing-key-info.txt` (**서명 키 — 절대 분실 금지**)
   - `assetlinks.json` (다음 단계에서 사용)

> PWABuilder 카드에 뜨는 이름은 `manifest.json`의 `name` 값입니다.
> ("구리 목양교회" → "목양교회"로 수정 완료)

### B-2. Digital Asset Links (assetlinks.json)
안드로이드 앱(TWA)이 주소창 없이 전체화면으로 뜨려면, 웹사이트가 "이 앱을 신뢰한다"고 증명해야 합니다.

1. 파일 위치(**origin 루트**여야 함): `https://byunghoonchoi76.github.io/.well-known/assetlinks.json`
   - → 그래서 별도 저장소 `byunghoonchoi76.github.io`를 만들어 호스팅
2. 파일 안에 **두 개의 지문(SHA-256)**이 들어감:
   - Google Play 앱 서명 키 지문
   - 업로드 키(PWABuilder 키스토어) 지문
3. 등록 후 라이브 확인

### B-3. Google Play Console 앱 등록
1. Play Console → **앱 만들기**
   - 앱 이름: 목양교회 기도
   - 기본 언어: 한국어
   - 앱/게임: 앱 / 무료
2. **프로덕션 또는 비공개 테스트** 트랙에 AAB 업로드
3. 스토어 등록정보:
   - 아이콘(512×512), 피처 그래픽(1024×500), 스크린샷
   - 짧은 설명 / 자세한 설명
4. **앱 콘텐츠**(11개 항목) 전부 작성:
   - 개인정보처리방침 URL
   - 데이터 보안(수집 데이터 신고)
   - 콘텐츠 등급 설문
   - 타겟 연령층
   - 앱 액세스 권한(로그인 테스트 계정 또는 "모든 기능 접근 가능")
   - 광고 포함 여부(없음) 등

### B-4. 비공개 테스트 → 정식 출시 (개인 계정 요건)
- 개인 개발자 계정은 **테스터 12명 이상 + 14일 비공개 테스트**를 거쳐야 프로덕션 출시 신청 가능
- 테스터: 12명의 Gmail 주소를 모아 비공개 테스트 트랙에 등록
- 14일간 유지 후 "프로덕션 출시 액세스" 신청

> **⏳ (미완성) 정식 출시 단계 — 테스터 12명 모집 후 이 부분을 채웁니다.**

## 7. 자주 묻는 질문 / 트러블슈팅

**Q. 앱이 "개인 레포지토리"에 의존하나요?**
→ 네. 현재는 최병훈 님 GitHub·Supabase·계정에 연결돼 있습니다. 교회 공용 계정 이전은 8번 참고.

**Q. iOS 개발자 이름이 "JEONGHUN OH"로 나옵니다.**
→ App Store의 "개발자" = **개발자 계정 소유자 이름**(오정훈 개인 계정)입니다. 코드 작성자와 무관. "목양교회"로 바꾸려면 **교회 조직(Organization) 계정**이 필요(8번 참고).

**Q. 스크린샷이 "파일 크기가 유효하지 않습니다"로 거부돼요.**
→ iPhone 슬롯은 **1206×2622 또는 1179×2556**만 허용. 투명도(알파 채널) 제거 필요.

**Q. 안드로이드 TWA가 주소창이 보이는 전체화면이 아니에요.**
→ `assetlinks.json`의 지문(SHA-256)이 맞는지, origin 루트(`/.well-known/`)에 있는지 확인.

**Q. 클라우드 작업 환경에서 EAS가 안 돼요.**
→ `api.expo.dev`가 막혀 있어 **로컬 PC(윈도우)**에서 EAS CLI 실행.
